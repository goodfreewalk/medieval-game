# medieval-game — правила для агента Qwen

@AGENTS.md

## Что это
Пошаговая средневековая стратегия: клиент на vanilla JS + canvas (public/),
сервер Node/Express/ws (server/server.js). ОБЩИЕ модули public/js/{state,logic,
units,terrain,maps,checksum,build}.js импортируются И клиентом, И сервером.

## Источник истины
Только файлы этого репозитория (ветка test). Внешние/старые снимки файлов
(например state.js/logic.js БЕЗ осадной регенерации и без lastHit) — УСТАРЕВШИЕ:
запрещено восстанавливать по ним код или «упрощать» текущую логику.
Уже починено и не переделывать: уведомления/ожидание (b797820),
места и кнопки золота (7fdf104), синхронизация и завершение партии (22acd83).

## Неприкосновенные инварианты
- Осадная регенерация: REGEN_CASTLE=10, REGEN_VILLAGE=5; под осадой 5/2;
  флаг unit.lastHit ставится в performAttack при реальной потере HP и
  сбрасывается в applyRegeneration в начале своего хода. Не удалять.
- Синхронизация: клиент и сервер считают идентично; turnChecksum + resyncRequest
  из зеркала. В общие модули НЕ вносить недетерминизм (Math.random, Date.now);
  случайность ботов — только на сервере.
- Карты симметричны (поворот 180°/зеркала); нейтралей 2+2 или 4+4 по вместимости;
  допустимые составы мест задаёт map.players.
- package.json: ровно один "type": "module".
- i18n: каждый новый ключ — в ru И en.

## Workflow и ветки
- Контур: test → тестовый сервер :8081 → ручной merge в main → прод :8080.
- Ветки агента: agent/qwen-<задача> (префикс agent/ занят Kimi — не пересекаться).
  Каждая задача в своём worktree: запуск qwen --worktree <slug>.
- PR только в test. Push в main и любой прод-деплой ЗАПРЕЩЕНЫ без явного
  подтверждения человека. git push --force, rm -rf, перезапуск прод-процессов — запрещены.
- BUILD (public/js/build.js) = версия протокола/логики: менять ТОЛЬКО при
  изменении игровой логики или протокола, не при рефакторинге/визуале.
- После правок общих модулей обязателен рестарт серверного процесса (иначе рассинхрон).

## Гигиена репозитория
- НЕ коммитить saves/ (внутри токены возобновления; репозиторий публичный) и node_modules/.
- Больше одного изменения в файле — выдавать/коммитить ПОЛНЫЙ файл, не диффы.

## Окружение этой машины
- Windows, пользователь COMP. Этот клон (medieval-game-qwen) — только Qwen.
  Клон Kimi C:\Users\COMP\medieval-game и его bat НЕ трогать.
- Майнинг pearl на 4×RTX3070: процессы, папки, логи, драйверы GPU НЕ трогать.
  Локальные LLM/Ollama/CUDA не ставить (8 ГБ RAM, карты заняты).
- Приватный Node агента может не видеть системные npm/npx: при необходимости
  использовать полные пути системного Node (уточняется пробой where.exe).

## Команды
- Синтаксис: node --check <file> по всем изменённым js.
- npm run check и scripts/deploy-test.ps1 появятся на шагах 7–8; до них не выдумывать.

## Workflow v2 (подтверждения владельца в чате)
### Фаза 1 — АВТО (без подтверждений)
- Правки в ветке agent/qwen-*; самотесты: npm run check, node --check изменённых, Playwright по http://localhost:8090 (консоль без ошибок).
- Рестарт dev-сервера :8090 после правок серверной логики; клиент — обновление страницы.
- commit + push ветки. Уведомление владельцу: «Локально готово: смотри http://localhost:8090» + список изменений + скрины. Деплой НЕ делать.
### Фаза 2 — только после фразы владельца «ДЕПЛОЙ ТЕСТ»
- merge ветки в test, push origin test, scripts/deploy-test.ps1, живая проверка :8081, уведомление «:8081 готов к сетевому тесту».
### Фаза 3 — только после фразы владельца «ПРИНИМАЮ ПРОД»
- merge test→main, push origin main, scripts/deploy-prod.ps1 -Confirm "ПРИНИМАЮ ПРОД", сверка HEAD/uptime прода, уведомление «Прод обновлён».
### Правила подтверждений
- Фразы «ДЕПЛОЙ ТЕСТ» и «ПРИНИМАЮ ПРОД» должны присутствовать в последнем сообщении владельца; агент не формулирует их за владельца и не деплоит без них.
- deploy-prod.ps1 требует -Confirm и пишет audit (дата, хэш main, фраза) в notes/deploy-audit.log; без -Confirm отказывает.
- «РЕВЮ» — запрос независимой проверки Kimi-ревьюером на любом этапе.
- Запреты прежние: force-push, rm -rf, майнинг/GPU, клон Kimi, saves/ в git, прямые правки файлов на VPS; прод-таймер отключён.
- Ручной deploy-prod.bat остаётся запасным путём владельца.

## Графика и ассеты через агента (и 3D потом)
- Владелец описывает словами → агент генерирует ассеты локально
  (scripts/gen-assets.mjs: бесплатный pollinations по умолчанию, retry 3/таймаут;
  DASHSCOPE_API_KEY / OPENROUTER_API_KEY только из env переключают на платных)
  или берёт готовые с диска. Вложения в чат не требуются никогда;
  ассеты только на диске и в git.
- Пайплайн: public/assets/raw/ → scripts/build-manifest.mjs (chroma-key = цвет
  из угла ±10 + despill, даунскейл tile:64 area-average) → public/assets/sprites/
  + manifest.json → клиентский рендер public/js/render/* (integer-scale 2x/3x,
  smoothing off, бесшовные края, замок/деревня/юниты = 1 клетка, эллипс-тени,
  горизонтальный flip, walk/attack — клиентские таймеры; старый рендер за
  флагом ?renderer=legacy до приёмки).
- Целевой стиль и правила: notes/art-style.md. Самотесты: npm run check,
  node --check изменённых, Playwright http://localhost:8090, скрины до/после в notes/.
- Фаза 1 заканчивается «Локально готово: смотри http://localhost:8090» + список
  изменений + скрины; деплой НЕ делать. Фазы 2/3 — только по фразам владельца
  «ДЕПЛОЙ ТЕСТ» / «ПРИНИМАЮ ПРОД».
- 3D потом: public/assets/models/ + scripts/gen-models.mjs (Meshy/Tripo/Rodin
  по env-ключам, .glb + manifest) + three.js-рендер; тот же регламент подтверждений.

## Git-транспорт изменений (обязательно)
- Единственный путь изменений: commit → push ветки → merge в test/main → git pull на сервере (fetch + merge --ff-only) + pm2 restart.
- Деплой-скрипты ОБЯЗАНЫ abort при грязном дереве или чужой ветке на сервере; test-каталог = ветка test, прод-каталог = ветка main.
- Запрещено: править файлы на VPS через ssh/scp/rsync/sed, деплоить мимо git, коммитить в main напрямую, переписывать историю.
- Перед push: npm run check зелёный; нет незакоммиченных игровых файлов; BUILD поднят, если менялась логика/протокол.
- notes/ и notes/backlog.md — локальные артефакты процесса (ignored), в git не коммитятся.
- Источник истины — файлы репозитория; внешние снимки (в т.ч. старые state.js/logic.js без осадной регенерации) в git не попадают никогда.
