# AGENTS.md — правила работы с проектом medieval-game

## О проекте
Браузерная мультиплеерная пошаговая стратегия.

- Прод: bitva-zamkov.ru (ветка `main`).
- Тестовая версия: bitva-zamkov.ru:8081 (ветка `test`).

- Клиент: чистый JavaScript (ES-модули) в `public/`, без сборки и без фреймворков.
- Сервер: Node.js + Express + ws в `server/`. Запуск: `cd server && npm install && npm start`.
- Игровая логика (`public/js/logic.js`, `state.js`, `units.js`, `terrain.js`, `checksum.js`) — ОБЩАЯ для клиента и сервера: сервер импортирует модули из `public/js`. Изменяя эти файлы, помни, что они выполняются и в браузере, и в Node.js — нельзя использовать там DOM/window/localStorage или Node-специфичные API.
- Синхронизация: сервер держит «зеркало» состояния и после каждой смены хода рассылает контрольную сумму; клиенты при расхождении перезапрашивают fullState. Не ломай эту схему.

## Ветки и деплой
- Все изменения пушатся в ветку `test`. Через минуту-две они сами появляются на тестовой версии: bitva-zamkov.ru:8081.
- Merge `test` → `main` делает только пользователь сам, после проверки на тестовой версии. Агент в `main` не пушит никогда.
- Автодеплой живёт на сервере: раз в минуту systemd-таймер `medieval-deploy.timer` запускает скрипт `/opt/deploy.sh`. Скрипт проверяет, не появились ли новые коммиты на GitHub, и если появились — подтягивает код и перезапускает нужный процесс:
  - `/opt/medieval-game-test` следит за веткой `test` → pm2-процесс `game-test` (порт 8081, своя папка `saves/`);
  - `/opt/medieval-game` следит за веткой `main` → pm2-процесс `game` (порт 8080, прод).
- Лог автодеплоя на сервере: `journalctl -u medieval-deploy.service`.

## Строгие правила
1. Никогда не коммить и не пушить в ветку `main`. Изменения пушатся в ветку `test` (напрямую или через ветку `agent/<короткое-имя>` с последующим merge в `test`).
2. Перед правками прочитай затрагиваемые файлы целиком, чтобы не сломать соседнюю логику.
3. Делай минимальные изменения: не рефактори и не «улучшай» код, который не относится к задаче.
4. Комментарии в коде — на русском языке, в стиле остального проекта.
5. Сообщения коммитов — короткие и понятные, на русском.
6. Push в GitHub и создание Pull Request — ТОЛЬКО после явного подтверждения пользователя словами «запушь» / «создай PR».
7. Не трогай папку `saves/` (там живые сохранения игроков) и `package-lock.json` без необходимости.
8. Если меняешь протокол сообщений клиент↔сервер (новые типы сообщений или поля) — обновляй обе стороны и подними версию в `public/js/build.js`, иначе старые открытые вкладки игроков сломают игру.

## Проверка перед сдачей работы
1. Синтаксис сервера: `node --check server/server.js`
2. Синтаксис изменённых клиентских модулей (каждого):
   `node --input-type=module --check < public/js/<файл>.js`
3. Если команда недоступна — сообщи об этом пользователю, не выдумывай результат проверки.
4. Если менялась игровая логика — прогони мысленно цепочку: действие игрока → применение на клиенте → применение на серверном зеркале → checksum. Опиши в ответе, что проверил.
